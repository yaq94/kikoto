# 個人資料

[English](../en/personal-data.md) · [简体中文](../zh-Hans/personal-data.md) · [繁體中文](../zh-Hant/personal-data.md) · [日本語](../ja/personal-data.md) · [한국어](../ko/personal-data.md)

登入後，在側邊欄開啟 **資料面板**，即可查看收聽日曆、報告與歷史。個人標籤位於 **設定 → 標籤**，**我的資料** 則是 **設定 → 帳戶** 的最後一個區段。頭像後方的帳戶選單與快速操作都能直接開啟其中任一項。它們只顯示你帳戶自己的資料。

## 個人標籤

可搜尋作品、社團或聲優標籤，包括未使用的標籤。重新命名會更新所有指派。合併會把指派移到既有的標籤、移除重複項，並刪除舊標籤。刪除會移除該標籤及其指派，但不會刪除作品或提供方中繼資料。

工作流程新的標籤預設值不含日期，因此重複執行時會重用同一個標籤。已儲存的既有範本會保留；如果較舊的排程應停止建立帶日期的標籤，請在工作流程中移除 `{date}`。明確指定的日期範本仍受支援。

## 資料面板

位於 **資料面板** 頂端的切換器決定頁面涵蓋的範圍：最近 30 天、最近 12 個月、全部時間，或某個日曆年。最後一項 **年份** 會展開有附日期收聽紀錄的年份，並顯示所選的年份。

**收聽日曆** 將一年依週排成欄、每天一格，依收聽時間上色，並附上該年的收聽天數、收聽時間與連續天數：選擇日曆年時顯示該年，選擇其他範圍時顯示過去一年。指向或輕觸某一天即可查看該日合計。

選擇日曆年時，頁面以該年的 **年度亮點** 開頭：該年的收聽時間、作品數與收聽天數，最常聽的作品、聲優和社團，最忙碌的一天及當天最常聽的作品，最長的連續收聽天數，該年首次聽到的作品，以及一天中最忙碌的小時。

針對所選範圍，收聽報告會顯示：

- 收聽時間、播放次數、作品數與活躍天數，以及每個活躍日的時間、每次播放的時間、最常聽作品所占時間的比例，和範圍內有收聽的天數占比。
- 依日、月或年繪製的圖表（日曆年以月為單位；超過三年後，全部時間會改以年為單位），以及平均值與最忙碌的期間。
- 最常聽的五個作品（可展開到十個），每個都附有其時間及其占該範圍內收聽時間的比例。
- 收聽節奏：週一至週五與每個週末日的平均收聽時間，以及依星期幾計算的平均。12 個月或全部時間的報告以日曆中的天數計算這一項，因此全部時間的報告描述的是過去一年。**時段分布** 會補充每小時的收聽時間（從午夜起），並標出最忙碌的小時。小時資料在收聽時記錄，因此伺服器開始統計小時之前的收聽不會計入其中。
- **口味畫像**：你所聽的內容與媒體庫的對比。雷達圖依每個標籤的收聽時間占比高出其媒體庫作品占比的幅度，繪出最多八個標籤。當足夠多的作品帶有相應數據時，標記會依發行年份、銷量和作品長度，把你的作品放在媒體庫的作品之間：軌道的中間代表媒體庫，收聽時間較長的作品權重較大。**你的評分** 將你給出的每個評分與相同作品的公開評分作對照。標記上方的幾句話說明突出之處，並給出你標記為已開始的作品中有多少已聽完或已標記為重聽。
- **標籤、聲優和社團**：各列出前五名（可展開到十名），每一項都會開啟其媒體庫搜尋、聲優頁面或社團頁面。**偏好度** 依其收聽時間占比高出媒體庫作品占比的幅度排名，並且只列出高於後者的項目：長條是收聽時間占比，標記是媒體庫占比。**收聽時長** 依其作品的收聽時間排名。一部作品會完整計入它的每個標籤和聲優。

作品是媒體庫所列出的那些：收聽某個作品的任何版本，都會計入該作品。

一天從你所在時區的午夜開始。**自動** 為初始設定，會跟隨每個裝置：收聽會計入播放它的裝置的當前日期，報告則結束於顯示它的裝置的當前日期。在 **設定 → 帳戶 → 時區** 中選擇一個時區，即可在所有裝置上使用同一時區。頁面底部會標明所使用的時區，並連結到該設定。收聽會在記錄時計入當天，因此變更時區只會套用到之後的收聽，已記錄的日期維持不變。

匯入的總計沒有日期，因此只計入全部時間。完整歷史依最後收聽時間排序，並顯示每個作品的時間、播放次數與最後收聽日期，收合在頁面底部，展開時才會載入。**清除歷史** 與前往 **我的資料** 的入口就在它旁邊。時間衡量的是實際收聽，不含暫停、緩衝與拖曳時間；調整播放速度不會讓時間倍增。同時運作的播放器各自獨立計算。用戶端中斷或斷線，可能讓部分時間沒有被回報。

歷史會保留在你的伺服器上，直到被清除，或其帳戶／作品被刪除。90 天後的推薦事件清理不會移除它。升級會保留剩餘的舊播放事件與續播時間戳記，且不會憑空捏造時長；先前已刪除的事件無法復原。清除歷史會保留標記、播放清單與續播進度。帳戶計數器會拒絕清除之前延遲送達的回報。

## 匯出與匯入

Kikoto 個人 JSON 第 2 版包含編號作品、無碼作品、系列和單集的穩定引用、原始標題，以及本人的評分、備註、收聽標記、續播資訊、累計收聽總計、作品標籤、自訂標籤定義和附圖示的有序收藏清單。系統「標記」由收聽標記推導。社團和聲優標籤僅包含定義，不含實體關聯和其他狀態。

備份不包含媒體、來源設定、端點、憑證、提供方中繼資料、原始工作階段和每日統計。來源引用是不透明識別碼，不包含本機路徑、來源內部編號或暫時媒體連結。

選擇檔案、Kikoeru 帳戶或資料庫，先查看預覽再匯入。「保留現有資料」保留既有個人記錄和同名清單；「覆寫」明確替換檔案提供的個人欄位和清單。收聽總計依最大值合併。同一共用物件的多份匯入評價有矛盾時，即使選擇覆寫也會整組略過；明細顯示本人現有評價和匯入評價，方便整理檔案。矛盾身分逐筆報告，其他可安全處理的記錄繼續匯入。已知但尚未登記的目錄條目、系列和單集在具備登記權限時按原評價層級恢復，缺少權限時整體拒絕匯入。

第 2 版可在具備登記權限時依檔案中的必要資訊還原缺失物件，不下載媒體，不改變既有共用關係。單集保留獨立評價層級；系列成員關係及共用關聯需透過資料編輯流程確認。未知來源引用會保留供後續傳輸，不建立來源連線。重複匯入重用引用。第 1 版和 Kikoeru 格式依既有作品編號及明確別名比對，缺失編號列出並略過。
單集身分可以攜帶顯式父系列身分。父級缺失、衝突或循環時會報告，且不會還原為獨立作品。檔案版本仍為第 2 版；沒有父級的單集維持原有行為，並報告父級未還原。

續播必須比對精確作品或版本及唯一的音軌標題、音軌號和光碟號。找不到或有歧義的音軌保留目前播放進度；第 2 版也保留未比對的匯入進度供後續匯出，不虛構媒體或跨版本換算時間軸。包含未解決第 2 版引用的清單整體保留。

匯入在單一交易內提交，只處理目前登入帳戶。限制為 10 MiB、20,000 個作品、5,000 個標籤定義、1,000 個清單、50,000 個清單項目或作品標籤關聯，以及每個作品最多 100 個額外穩定引用。

## Kikoeru

Kikoeru JSON 檔案可接受評價陣列、`reviews` 陣列，或 API 的 `works` 陣列。請只使用單一帳戶的資料，並包含所有需要的頁面。代碼使用 `primaryCode` 或 `source_id`；數字的 `work_id`／`id` 是商品編號。把商品類型編碼進 ID 的分支版本（類型 × 10¹² + 數字，其中 RJ、BJ、VJ 與 CC 分別是類型 0–3）會被解碼。與商品代碼無關的 ID 必須先轉換。支援個人的 `userRating`／`user_rating` 與 `review_text`；不會匯入提供方的評分。

**Kikoeru 帳戶** 會替你讀取資料。選擇一個已設定的相容 Kikoeru 來源，或輸入伺服器的 API 位址，然後以無（適用於關閉登入的伺服器）、權杖，或使用者名稱與密碼登入。伺服器會透過 `POST /api/auth/me` 登入，透過 `GET /api/review` 逐頁讀取，並且在 Kikoeru 伺服器提供時，讀取你擁有的播放清單，包括其喜歡與已標記清單。沒有播放清單的伺服器只會匯入評價。結果會和檔案一樣，經過相同的預覽與匯入。

**Kikoeru 資料庫檔案** 會上傳開源版 Kikoeru 的 SQLite 資料庫（最大 512 MiB），並只讀取指定帳號的評價。上傳最長可持續 15 分鐘。請在 Kikoeru 停止或閒置時複製檔案，才能包含最近的寫入。該資料庫沒有播放清單。

在權杖、密碼、手動輸入的位址或資料庫離開瀏覽器之前，Kikoto 會說明風險並要求確認：

- 憑證會經過 Kikoto 伺服器。它們只用於該次請求，絕不會被儲存或寫入日誌，但營運該伺服器的人有可能擷取到它們。
- Kikoeru 伺服器會看到來自 Kikoto 伺服器網路位址的登入。第三方網站可能因此標記或限制該帳戶。
- 權杖等同於你的帳戶，並且可能長時間有效。
- Kikoeru 資料庫包含該伺服器上的每個帳戶，包括密碼雜湊。上傳的檔案在讀取期間存放於暫存檔，讀取完成後立即刪除。

這些請求絕不會跟隨重新導向，因此憑證只會送到你選擇的位址。手動輸入的位址必須是公開位址，除非你是管理員，或是管理員開啟了 **設定 → 媒體庫 → Kikoeru 帳戶匯入 → 允許所有帳戶使用區域網路位址**。該開關會讓任何已登入的帳戶都能讓伺服器連線到其區域網路中的裝置。沒有可用商品代碼的資料列會被略過並計數，同一時間最多只會執行兩個帳戶或資料庫的讀取。

| Kikoeru 進度 | Kikoto 標記 |
| --- | --- |
| `marked` | 想聽 |
| `listening` | 聆聽中 |
| `listened` | 已完成 |
| `replay` | 重聽 |
| `postponed` | 已擱置 |
| 空白／null | 未標記 |

此對應依循上游的 [Kikoeru review API](https://github.com/kikoeru-project/kikoeru-express/blob/unstable/routes/review.js)。
