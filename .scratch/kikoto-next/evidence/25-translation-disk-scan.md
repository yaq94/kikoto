# 25：翻译磁盘统计的读取范围

基点 `aff8438d`，对应本文件同提交的磁盘统计修复。应用 schema 保持 111，未增加依赖、缓存、期限或重试。原始日志在仓库外 `reports/20261107-remediation/`。

## 实际失败与定位

`de28db0c` 隔离实例第一次 `/api/settings/translation/runtime` 读取超过原 15 秒预算。实际数据库的只读 Go 诊断使用同版代码、2 CPU／2 GiB 限额：有效语料统计 2.511 秒、缓存分类 0.928 秒、磁盘统计 8.153 秒，总计 11.61 秒。缓存命中时的快速返回不能证明冷请求通过。

磁盘统计以 CASE 汇总翻译表、索引与 FTS shadow 表，但没有约束 `dbstat` 的输入，因此遍历其他目录、观测和发布快照的页面。SQLite 文档及实现明确支持 `name` 等值约束，查询计划中的 0x02 表示按名称读取 B-tree。只读 SQL 对照把同一名称集合放入 `WHERE name IN (SELECT name FROM sqlite_schema ...)` 后，两组页字节数完全一致；同机原生 SQLite 耗时从 916.212ms 降至 78.590ms。

实现只添加这个输入约束，保留既有 CASE 分类、页归属比例、软预算与持久语料保留规则。不会把无关数据库树的大小计入翻译预算，也不再扫描其页面。
