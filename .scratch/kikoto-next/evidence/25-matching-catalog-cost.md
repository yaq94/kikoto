# 25：发布准备期的匹配位置读取

基点为 `72778052`，对应本文件同提交的 SQL 修复。原始日志位于仓库外 `reports/20261107-remediation/`，实际数据库、端点、路径与原始调用栈只留在受限运维目录。

## 实际触发与诊断

`72778052` 的实际隔离索引续跑在发布调用等待约 5.1 秒后以 SQLITE_BUSY 失败，准备中的发布操作仍被保留，未被计为完整。随后使用仅添加信号调用栈采集的临时诊断构建，捕获到同一时刻发布器等待写锁、后台作品匹配正在执行 `loadAssociationObject` 的位置 SQL。诊断构建不用于部署验收。

匹配的位置 SQL 在 entry 与 series member 上使用跨表 OR，查询计划扫描完整 entry 投影并物化系列成员；每比较一个候选重复执行。真实库包含约 12 万条身份，当前来源约 4.2 万条，其余包括保留的无来源身份，不能为加速而删除这些记录。

## 实现与验证

在同一查询内先通过直接目录引用、共享作品身份与系列成员三条分支选出相关 entry id，去重、排序并保留原 101 条上限，再读取同一已发布快照中的位置与成员字段。原匹配候选上限、5 秒期限、101 条位置边界、权限、私有评价和身份语义不变，无新缓存、迁移或依赖。

- `matching-catalog-red.log`：120,000 合成条目、42,624 来源条目、600 系列及准备中快照，真实 HTTP 请求评估 102 候选；旧 SQL 在原 5 秒期限返回503，exit1。
- `matching-catalog-green.log`：完全相同数据与断言，HTTP200，4,123.181 ms；102 候选完整保留且结果为歧义待审阅，不产生关联；exit0。规模测试沿用 opt-in H 资源入口，不改变普通 race 的行为验证边界。
- `matching-catalog-regression.log`：64项顶层普通回归通过，exit0；覆盖匹配、共享关联、拆分、发布前快照、私有状态及恢复。该次默认跳过的规模测试另由上述显式 opt-in 命令验证，不记为普通套件通过。
- `matching-catalog-race.log`：5项匹配和发布race退出0，102候选请求2.240秒；`matching-catalog-race-recovery.log` 的系列关联与实际重启恢复2项race亦退出0，包耗时49.680秒。
- `matching-catalog-static.log`：格式、vet、固定lint2.13.1、敏感扫描和证据扫描全部exit0。
