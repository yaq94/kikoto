# Kikoto 下一阶段规格

**Status:** ready-for-agent
**设计状态:** 已确认（Q31）；用户故事、验收要求与测试边界作为实施合同。
**Implementation:** in-progress；01–06 已集成并完成所属验收，07–13、15、16 已完成本地实现并集成，18 迁移完成一致性与 19 前端 CI 修复已合入；14 功能、真实媒体 LIVE、真实索引覆盖、完整 CI、最终审查和部署验收按执行记录推进。
**执行授权:** 用户已授权本规格全部功能实现、必要依赖安装、测试、数据库迁移、部署与回滚；进度及证据见[执行记录](execution.md)。

## Problem Statement（问题）

用户希望在同一个 Kikoto 音声库中浏览、搜索和评价多个来源的内容，但当前内容语言主要选择已有的多语言元数据，不能翻译任意标题、简介和目录名称。已有多源目录在来源状态未知时可能无法正确显示；评分备注的保存入口没有覆盖所有远端和无码内容。

新增的 [OpenList 音声目录站](https://www.asmrgay.com/) 同时包含有编号与无编号音声、系列与单集，以及压缩包或字幕目录。直接把来源路径当成作品身份，会在跨源关联、系列归组、目录改名时混淆个人记录。全量搜索、持续更新和翻译还必须适应有限的服务器资源。

## Solution（方案）

1. 管理员在 Kikoto 统一配置现有翻译接口、密钥和模型调用名，首选 Index-Translate-35B-A3B。用户切换显示语言后，当前浏览及动态加载内容自动获得译文；界面语言保持独立，原文随时可查看。
2. 对符合条件的匿名音声建立来源索引，提供统一卡片、搜索、目录与播放入口。未登记作品也可检索；保存个人评价时才按需要登记作品信息，不下载音频。
3. 同一作品在一处呈现多个来源目录。来源状态后台更新，切换浏览目录不打断当前播放；明确选择音轨才改变播放内容。
4. 编号作品、无码作品、系列和单集都能保存私有评分备注。同一评价对象跨源共享当前用户的记录，系列与单集独立；关联和拆分遵守本人确认、全库资料权限及记录保留规则。
5. 使用可调整的请求、缓存和存储上限，逐批持久化索引进度并支持恢复。每天更新不会制造重叠全站任务，未知或失败范围不会被标成完整覆盖。

## User Stories（用户故事）

1. **US-01**：作为管理员，我希望保存统一翻译接口地址、密钥和模型调用名，以便所有用户使用同一翻译服务。
2. **US-02**：作为管理员，我希望用实际翻译请求验证配置并看到可理解的结果，以便区分配置错误、服务失败和可用模型。
3. **US-03**：作为普通用户，我希望使用翻译但不能读取密钥或更改全局配置，以便保持清晰的权限边界。
4. **US-04**：作为浏览者，我希望标题、简介、系统标签和目录显示名随显示语言翻译，以便阅读不同来源的内容。
5. **US-05**：作为浏览者，我希望显示语言与界面语言分别按用户保存且互不改写，以便独立选择内容和菜单的语言，不影响其他用户。
6. **US-06**：作为浏览者，我希望翻页、打开作品和展开目录后新增的内容也遵循显示语言，以便动态内容与当前页面一致。
7. **US-07**：作为用户，我希望社团、声优名称、个人标签和备注保留原文，以便名称识别和私人文字不被自动改写或发送给翻译服务。
8. **US-08**：作为浏览者，我希望默认阅读译文并能查看原文，以便核对翻译。
9. **US-09**：作为浏览者，我希望等待或失败时仍能阅读原文并重试，以便翻译故障不阻断浏览。
10. **US-10**：作为浏览者，我希望连续切换语言时只显示当前选择对应的结果，以便迟到请求不会覆盖新选择。
11. **US-11**：作为浏览者，我希望重复阅读复用译文，而原文或模型变化后更新缓存，以便减少重复费用并避免过期译文。
12. **US-12**：作为繁体中文使用者，我希望通过简体译文和成熟转换规则得到繁体内容，以便保持可控的一致显示。
13. **US-13**：作为管理员，我希望调整翻译并发、排队、超时和缓存上限，以便控制接口请求与服务器存储。
14. **US-14**：作为浏览者，我希望在统一卡片与搜索中找到新源的全部符合收录条件的匿名音声，以便不必先逐个跟踪作品。
15. **US-15**：作为浏览者，我希望没有发行编号的音声也能浏览、播放和评价，以便编号不是内容准入的唯一条件。
16. **US-16**：作为浏览者，我希望仅压缩包或字幕目录不会伪装成可播放作品，以便搜索结果符合音声播放用途。
17. **US-17**：作为浏览者，我希望未登记的来源索引条目仍可搜索和打开目录，以便搜索范围不取决于个人收藏或登记行为。
18. **US-18**：作为已有用户，我希望原来的编号入口、作品关系和个人数据在升级后继续有效，以便新增无码能力不损坏现有音声库。
19. **US-19**：作为用户，我希望作品使用稳定身份而非译名或临时来源路径，以便跨源切换和目录变化后保留正确记录。
20. **US-20**：作为收听者，我希望同一作品显示多个来源目录并能分别浏览，以便选择实际需要的来源与版本。
21. **US-21**：作为浏览者，我希望先看到已有来源结果，再后台检查未知或过期状态，并可手动刷新，以便打开页面不必等待全部来源。
22. **US-22**：作为收听者，我希望切换来源标签时当前音轨、队列和位置保持，以便比较目录不打断收听。
23. **US-23**：作为收听者，我希望点选音轨从头播放，并通过继续按钮恢复进度，以便明确控制开始位置。
24. **US-24**：作为具有相应权限的用户，我希望对所有来源的作品保存评分和备注，以便记录收听评价。
25. **US-25**：作为用户，我希望同一评价对象的个人记录跨源一致，以便更换来源不产生多份评价。
26. **US-26**：作为用户，我希望评价未登记作品时只登记必要信息，以便作品进入作品库而不下载音频。
27. **US-27**：作为用户，我希望编辑或清除自己的评分、备注，且未提交字段不被覆盖，以便安全维护记录。
28. **US-28**：作为用户，我希望其他用户不能读取或覆盖我的个人记录，以便共用作品库仍保有个人边界。
29. **US-29**：作为浏览者，我希望无码系列显示一张卡片并在内部列出单集，以便按系列整理内容。
30. **US-30**：作为浏览者，我希望只有明确系列证据才自动归组，格式副本和分轨不成为额外作品，以便不同作品不被误混。
31. **US-31**：作为用户，我希望系列和每个单集分别保存评价，以便既记录整体感受，也评价具体单集。
32. **US-32**：作为资料编辑者，我希望预览并确认全库共用的关联和归组，以便了解对象、来源和版本将如何变化。
33. **US-33**：作为用户，我希望仅高置信且唯一的作品候选自动关联，其余保持独立待确认，以便自动整理不会任意混淆作品。
34. **US-34**：作为用户，我希望同一用户在两对象上的冲突评价先保留并暂停关联，以便本人决定最终内容。
35. **US-35**：作为记录本人，我希望无需额外资料编辑权限就能处理自己的冲突，以便共享操作不会迫使他人代替我决定。
36. **US-36**：作为参与确认的用户，我希望过期预览不能直接提交，未完成操作可在重启后继续，以便并发修改和中断不丢失选择。
37. **US-37**：作为记录本人，我希望误关联拆分时选择合并后记录的归属，必要时两边保留，以便纠正关联而不丢弃评价。
38. **US-38**：作为用户，我希望可靠认回的目录改名更新定位，证据不足时保留原对象和候选，以便改名不错误转移个人记录。
39. **US-39**：作为管理员，我希望看到完整索引的分区、目录、条目与失败进度，以便知道真实覆盖范围。
40. **US-40**：作为管理员，我希望每天更新并可手动刷新，已有扫描复用或续跑，以便内容持续更新且不重复消耗资源。
41. **US-41**：作为管理员，我希望索引取消、失败或重启后可恢复，以便不丢失已完成进度或产生重复条目。
42. **US-42**：作为浏览者，我希望来源暂时失败只影响该来源状态，卡片与个人记录保留，以便仍能使用其他来源。
43. **US-43**：作为用户，我希望全源确认删除后仍保留无来源卡片，手动清理不删除他人评价，以便失联内容仍可追溯。
44. **US-44**：作为用户，我希望导入导出覆盖编号、无码、系列与单集记录，兼容旧编号格式，以便迁移和备份不会静默丢数据。
45. **US-45**：作为管理员，我希望扫描和缓存受存储、并发和响应上限控制，低空间时可暂停，以便浏览、播放和个人记录不被后台任务拖累。
46. **US-46**：作为维护者，我希望用可复现的非视觉验收证明当前产物的行为，并明确未覆盖项，以便不把文档、健康检查或模拟结果当成功能交付。

## Implementation Decisions（实现决定）

### D-01：基线、交付与复用

- 应用实现起点是官方 v0.8.3；需求整理时的 main 包含其后的文档提交，不能把文档提交当成新版应用。未部署定制源码不整体恢复。
- 复用既有语言偏好、出站传输、作品与版本关系、个人状态、系列目录、SQLite 检索和持久任务机制；只为明确缺口增加接口或状态。
- 每个独立修改携带相关文档、行为验证和 Git 提交并推送。按已确认授权执行生产部署、数据库迁移与必要回滚；部署前完成当前产物验收、备份和恢复检查，执行结果单独留证。旧定制源码清理不属于本期任务。
- 发布后的迁移保持不可变；新增身份契约采用兼容扩展，再按用户行为接入，保留旧编号入口。需要新依赖时在实施工单列明用途和版本，在已授权范围内安装并验证。

### D-02：翻译配置与调用

- 管理员统一配置 API 基础地址、API 密钥和实际模型调用名，首选 Index-Translate-35B-A3B。配置持久保存，密钥仅由服务端使用，读回掩码，不进入普通用户响应或日志。
- 权重仓库名、接口 model 值与展示名分别处理；自定义调用名不得被客户端自动改成其他名称。通过兼容接口使用官方单条 user 翻译模板，根据接口能力关闭推理输出。
- 未配置或配置不可用时保留原文并报告状态。空输出、截断、格式错误、鉴权失败、限流和超时不当成成功译文；超时不自动反复生成。
- 所选模型通过已有服务接口调用；本期不在 Kikoto 服务器加载模型权重或新增模型托管。

### D-03：翻译展示与缓存

- 优先使用当前作品与版本已有的目标语言字段，缺失时翻译。范围为标题、简介、系统标签、目录显示名，包含动态加载内容。
- 社团、声优名称及个人标签、备注保持原文；这些受保护内容不提交自动翻译。译文按文本渲染，不解释为可执行内容。
- 显示语言与界面语言分别按用户保存，共用管理员配置的翻译服务；一名用户的偏好变更不改写其他用户的偏好。显示语言只改变文字，不改变当前音声版本、选中来源、真实文件身份、音轨或进度。原文语言选项不触发自动翻译。
- 等待或失败显示原文与状态；成功默认仅显示译文，可查看原文并重试。语言变更、页面离开和会话变化不得让旧结果覆盖新状态。
- 缓存至少区分原文、目标语言、模型和模板版本，且不能绕过原内容的读取权限。同请求去重；繁体由简体译文经成熟转换规则生成，保护名称，区分简繁展示与缓存。

### D-04：来源索引与稳定身份

- 收录范围为目标 OpenList 站点中全部匿名可访问、可直接播放的音声，包括无码内容；仅压缩包或仅字幕的目录排除。作品含音频及附带字幕或压缩包时仍可收录。
- 来源索引条目在未登记为作品库作品时也可搜索、显示统一卡片和浏览目录。跟踪、评分、收藏或登记不是全量收录前提；索引不下载或镜像音频。
- 作品身份、作品版本、系列、单集和来源位置分别保存。发行编号可缺失但不能伪造，无码对象需要稳定内部标识和来源定位映射；现有编号访问、关系与记录保持兼容。
- 目录显示名、来源路径和临时链接签名不能单独充当永久身份。可靠认回时更新定位；证据不足保留原对象、记录与待确认候选。
- 来源适配按能力与类型工作，不依赖显示名称。原始媒体链接按需解析、失效后重新取得；遵守既有出站 URL、重定向、凭据、地址与响应大小边界。

### D-05：索引更新与来源生命周期

- 使用持久目录队列逐目录、逐页遍历，完成批次后落盘检查点并释放数据库与执行资源。上游搜索用于补充或核对，不能单独证明完整覆盖。
- 分区状态、已扫描目录、已发现条目、失败、权限限制和待确认空目录分别呈现；分母未知时不伪造全站百分比。
- 初次索引完成后每天触发更新，允许手动刷新；同一来源已有扫描时复用或续跑，不排入重叠全站任务。
- 仅对成功完整扫描的相应范围判断未再出现的位置缺失。失败、维护和未确认空目录不证明永久删除；单源失效不改变其他来源状态。
- 临时失联与全源确认删除均保留卡片及个人记录，标记相应状态。手动清理受资料权限限制；仍有个人记录引用时延后共享对象物理删除，不能级联删除他人评价。

### D-06：多源目录与播放

- 先显示已有来源结果，后台检查未知或过期来源，提供手动刷新。unknown 必须能进入检查和加载流程，不能永久阻止来源目录出现。
- 单个来源失败保留其他结果和详情主体。切换来源标签只改变浏览目录，当前播放、队列及位置保持。
- 点选具体音轨才改变播放内容；普通点播从头开始，继续按钮沿用保存进度。作品关联不证明不同版本的音轨和时间轴相同。

### D-07：个人评价与系列

- 扩充既有作品个人状态的评分与备注编辑，并为系列提供独立个人状态；同一评价对象跨源共享当前用户记录，系列和各单集互不覆盖。
- 沿用已有个人评分取值及清除语义，未提交字段保持，显式清除只影响指定字段。公共评分和作品元数据不与个人记录混用。
- 未登记对象保存个人状态时，按现有登记和权限边界登记必要信息，不生成媒体下载任务或写入受管理音频。
- 明确系列名、集数或系列目录证据才自动归组；否则独立展示、提供确认入口。格式副本和分轨归对应作品或单集，不能成为新的作品或单集。
- 系列卡片内部列出独立单集；人工归组、关联、拆分为全库共用资料，沿用资料编辑权限。

### D-08：关联、冲突与拆分

- 可靠发行编号和已有作品关系优先；无码匹配使用标题、声优等多项可复核证据。仅高置信且候选唯一时自动关联，歧义与矛盾保持独立待确认。
- 冲突按同一用户在两个对象上的同一字段判断；不同用户评价不同不构成冲突。两份已填写值不同时保留并暂停，空值不覆盖已有内容。
- 资料编辑者发起共享操作，受影响用户只处理自己的记录，无需额外资料编辑权；编辑者不能代替他人确认。所有必要确认完成前保持待处理，未回应者的记录保留，其他用户仅见必要状态。
- 预览展示对象、来源归属及本人可处理记录。提交前复核相关版本；过期预览要求刷新，关联或拆分与记录归属一致提交。
- 拆分保留合并前依据；合并后新增或修改记录由本人选择一侧或两侧保留，不能自动拼接、分配或丢弃。操作和选择可恢复。

### D-09：个人数据兼容

- 导入导出表达编号作品、无码作品、系列及单集的稳定身份与本人记录，兼容旧有效编号格式；不能静默跳过新增对象。
- 重复导入不重复对象，冲突保持可审阅且不静默覆盖。不得因个人数据导入越权修改共享关系、泄露他人记录或下载媒体。

### D-10：初始资源预算

| 范围 | 初始默认值与可观察边界 |
| --- | --- |
| 翻译 | 全局并发 1，待处理最多 32 项，单次上限 60 秒；取消不再需要的排队项，超时不循环重发。 |
| 译文缓存 | 磁盘上限 256 MiB；只淘汰可重建译文，个人记录与来源身份不属于淘汰对象。 |
| 目录扫描 | 并发 1，每秒最多 1 次元数据请求，每次响应最多 2 MiB；逐批落盘和保存恢复位置。 |
| 磁盘 | 可用空间低于 2 GiB 时暂停新增索引与缓存并提示；已存内容仍可读，个人记录保留，暂停不等于完成。 |

管理员可调整这些值，实际数据测量用于校准。达到上限必须产生可理解的排队、拒绝、暂停或失败状态，不能无界增长或悄悄丢弃尚未完成的工作。

## Testing Decisions（测试决定）

### 测试什么

- 好的测试通过公开行为证明契约：从真实路由写入，再由公开查询回读；观察响应、个人记录、来源状态、任务结果和外部请求边界。失败用例必须能在缺陷存在时失败。
- 不按内部函数、私有状态布局或调用顺序写镜像测试，不模拟被测业务。外部模型、OpenList、时钟、磁盘余量和故障点可以在边界替换，真实鉴权、数据库、任务与归属逻辑保留。
- 每张工单自带对应验收，不把缺失测试推给最终整合票。相同事实优先在最低成本且足以证明行为的高层入口验证，避免逐层重复断言。
- 上表验收条件是交付合同，不代表本轮已执行功能测试或已通过。

### 主入口与必要补充

| 入口 | 覆盖内容与复用先例 | 不足以证明的内容 |
| --- | --- | --- |
| H：应用 HTTP＋真实迁移 SQLite | 复用现有账户语言 PATCH 后 GET 回读、会话登录和隔离临时数据库模式；覆盖翻译、索引、个人状态、共享操作、权限、迁移与数据传输。上游仅在网络边界使用本地服务桩。 | 不能单独证明 React 点击绑定、页面异步覆盖、媒体元素状态或真实进程恢复。 |
| R：同一应用跨生命周期验证 | 复用持久任务与检查点测试基础，关闭并重新打开真实应用或进程及同一测试库，覆盖续扫、每日调度、待确认操作与迁移。 | 仅调用“重排队”函数或模拟 lease 不等于实际重启验证。 |
| F：少量 Playwright 纯功能 | 用户已确认保留。复用现有内容语言、延迟目录响应和生成 WAV 的播放持续场景；检查语义控件、文本、请求与媒体状态。至少保留一条真实前后端联通链路，外部服务仍可用桩。 | 路由拦截的 UI 测试不证明前后端联通；合成 WAV 不证明真实源的全部编码、链接和浏览器兼容性。 |
| U：必要的纯状态补充 | 复用现有 Vitest，针对明确的匹配、排序、缓存键或状态转换规则提供小样例。 | SSR 字符串和纯逻辑测试不代替用户交互；不引入大型伪造组件运行时。 |
| LIVE：真实接口样例 | 在 H 的真实服务配置下，选取少量 Index 试译与匿名媒体 Range/定位读取，记录脱敏的版本、请求结果、耗时和文本语义检查。 | 健康检查不证明模型可用，目录/get 成功不证明解码或播放，抽样不证明全站完整。 |

### 浏览器测试边界

- 不进行真实浏览器视觉验证；截图、像素对比、几何布局、字体、裁切、响应式观感及人工视觉签收均不是本期验收要求。
- 保留用户批准的少量浏览器纯功能用例，明确选择无截图、无布局断言的测试体，并对本期执行配置关闭截图采集。不能直接把混有布局断言和主动截图的整套既有测试称为“非视觉测试”。
- 复用语义角色、标签、文本和可观察完成条件，不依赖 Tailwind 类、偶然 DOM 父子结构或固定等待时间。
- 现有 Vitest 没有 DOM 交互环境；本期不为规避浏览器而新增测试技术栈。已有全仓测试不因此删除或改写，新增功能用例单独筛选。

### 数据、网络与真实样例边界

- 使用最小手工合成数据、确定性构造器、保留编号 RJ00000000–RJ00000099、通用名称、保留域名、固定时间和临时目录。无码夹具必须真实没有发行编号，不能用伪造 RJ 绕过准入。
- 网络桩覆盖分页、重复页、目录变化、受限或失败分支、空目录、过期链接、限速、取消，以及模型空输出、错误、截断和迟到响应；数据集预先列明应收录集合。
- 不复制或轻度脱敏真实作品库、数据库或上游大响应作为夹具；密钥、真实私有端点和用户备注不进入仓库或测试报告。
- 常规测试不依赖公网或消耗真实翻译额度。LIVE 在显式配置、有限请求量的隔离环境执行，使用非敏感文本与最小媒体范围；不能把真实全站扫描放入普通 CI。
- 真实样例失败或凭据未配置时记录为未验证，不以模拟测试通过替代。上线前要有对应模型与媒体协议证据；文本质量可直接审阅 API 文本，无需浏览器视觉验证。
- 全量性先用已知完整的合成树证明遍历和过滤契约，再以实际索引运行的分区、时间、进度与失败报告说明真实覆盖；上游搜索命中数不能当作作品总数。

### 执行与完成边界

- 沿用 Makefile 入口：后端按影响运行 backend-test 或 ci-backend；前端纯逻辑与构建使用 frontend-coverage 或 ci-frontend；定向功能场景通过 frontend-e2e 的 E2E_ARGS 选择；已构建服务的非浏览器 HTTP 检查使用 production-smoke。
- 按工单依赖执行实现、应用构建、功能测试、有限真实翻译与媒体验证，并在指定环境执行完整来源索引和部署验收。只有对应当前产物且实际取得的证据可计入完成状态。
- 部分 Make 目标会安装依赖或浏览器。用户已授权本期必要安装；执行前核实环境、用途与版本，沿用现有测试技术栈和非视觉边界。
- 迁移、身份兼容、私有记录与恢复必须针对当前产物验证；测试报告标明版本、命令、退出状态、受控与真实覆盖范围，以及未通过或未执行项目。
- 不做浏览器视觉验证意味着不能宣称布局、视觉无障碍或跨浏览器观感已验收。只有指定浏览器和合成媒体的功能测试时，也不能宣称所有真实编码、音质、无缝切源或其他浏览器兼容性已验证。

## Out of Scope（范围之外）

- 旧定制源码清理；此项不属于本期功能实现、测试和部署任务。
- 强制使用“沉浸式翻译”官方产品、要求用户安装插件、本地托管模型权重或新增付费计划。
- 自动翻译社团、声优、个人标签和个人备注；翻译音频内容、自动转写或新增字幕翻译。
- 登录、破解或绕过新源密码目录与访问限制；仅压缩包或字幕目录的媒体解包与播放。
- 用仅搜索已发现、已跟踪或已登记内容替代完整来源索引。
- 自动下载或镜像音频、以评分触发媒体下载、将系列成员合并为同一录音、依据关联猜测跨源时间轴。
- 代替其他用户处理或删除私有记录，以及无确认地覆盖冲突评价。
- 真实浏览器视觉验证、截图验收、像素或布局比较、原生客户端视觉改版与全新测试框架。
