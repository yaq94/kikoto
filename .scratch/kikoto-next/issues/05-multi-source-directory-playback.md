# 05: 多源目录刷新与播放状态隔离

**What to build:** 作品详情先呈现已有来源目录，后台检查未知或过期来源；用户刷新或切目录标签时当前播放继续，点选音轨才切换。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**Implementation:** resolved；本地实现与 H/F 已验收；生产部署验收见 17（含真实媒体 Range 复验）。

**证据:** [05 来源与播放验证](../evidence/05-source-playback.md)。既有编号来源与 catalog 来源 H/F 验收通过；已吸收 02／07 并复验真实 path、内容语言隔离、无码多源和播放游标一致性。本票无新增迁移。

**测试契约:** H 真实路由、登录会话与迁移 SQLite；F 使用独立 API 和合成 WAV，关闭截图、trace、video。测试覆盖逐源 freshness、未知来源探测、故障恢复、目录切换与显式播放／继续；必要 U 仅保护纯来源状态规则。

**依据:** [正式规格](../spec.md) · [工单总览](../ticket-proposal.md)

## 验收范围

**主责:** AC-10、AC-11

**共同:** AC-23、AC-27、AC-28

AC-23 的来源间故障隔离；完整来源生命周期由 10 负责。

## 验收清单

- [x] 选择可复现的多源样例；未知或过期来源必须实际进入检查流程，目录归属正确且可手动刷新。
- [x] 单源失败保留其他目录、已知详情和可恢复状态，不让 unknown 永久阻止加载。
- [x] 切换标签不替换当前音轨或队列，不重置、不跳转播放位置；正常播放进度继续推进。
- [x] 点选另一音轨从头播放，继续按钮恢复已保存进度；不根据作品关联猜测不同版本的时间轴相同。
- [x] 采用通用来源能力契约，复用现有目录和全局播放器；新增出站路径自行覆盖 AC-27。
